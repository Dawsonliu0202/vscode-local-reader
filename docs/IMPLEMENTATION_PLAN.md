# VS Code 本地阅读插件：实现方案

版本：v0.4.1（记录合并与分区点击分页阅读）  
日期：2026-10-29  
状态：用户已确认并完成首版实现，本文保留设计依据  
需求依据：[功能描述 PRD](./PRD.md)

## 1. 技术路线

采用 **TypeScript 扩展宿主 + 一套轻量 Webview 阅读界面 + 本地文件存储**。三种外观复用同一套阅读逻辑，通过不同的 VS Code 容器展示。

| 范围 | 方案 | 选择原因 |
| --- | --- | --- |
| 扩展主体 | TypeScript、稳定版 VS Code Extension API | 使用官方扩展能力，避免依赖非公开接口 |
| 阅读界面 | 原生 HTML / CSS / TypeScript | 首版页面有限，无需 React、Vue 或额外状态框架 |
| 编辑器阅读 | `window.createWebviewPanel` | 可控制标签标题与阅读样式 |
| 侧栏阅读 | 资源管理器中注册 `WebviewViewProvider` | 可与文件树并列，避免另建复杂导航 |
| 底部阅读 | 原生 Terminal 视图 + 移入同容器的阅读 Webview | 左侧真实 Shell，右侧正文，使用 VS Code 原生分隔条 |
| 书架与统计 | Activity Bar 书本图标 + 同一管理 Webview 的两个页面 | 点击图标直接进入侧栏管理 |
| 存储 | `ExtensionContext.globalStorageUri` 下的 JSON 与书籍副本 | 跨本地工作区保留，无需数据库和服务端 |
| 构建与安装 | esbuild 打包，VSCE 生成 VSIX | 最终支持本地安装和离线使用 |

VS Code 官方支持在编辑器、侧边栏和面板内承载 Webview，因此三个模式可以共享页面与消息协议。[Webview 官方说明](https://code.visualstudio.com/api/extension-guides/webview)、[Views 与容器声明](https://code.visualstudio.com/api/references/contribution-points#contributes.viewsContainers)。

不采用微服务、数据库、依赖注入框架、通用插件系统或独立阅读器 SDK。0.2 直接复用 VS Code 原生终端，不额外实现 PTY、Shell 输入桥接或 Webview 内终端模拟器。

## 2. 模块划分

以下是职责划分，可以直接使用少量文件实现，不要求每个模块拆成多个层级。

| 模块 | 主要职责 |
| --- | --- |
| 扩展入口 | 注册命令、快捷键、视图、配置项和生命周期事件 |
| 导入模块 | 选择文件、内容哈希、TXT 解码、EPUB 解析、生成统一正文 |
| 本地存储 | 保存书籍与状态，串行写入、备份和失败恢复 |
| 阅读控制器 | 持有当前书籍和位置，路由操作，管理三个容器与隐藏状态 |
| 阅读记录 | 会话计时、空闲判断、日期拆分，生成统计数据 |
| Webview 页面 | 书架、正文、目录与统计展示，三套阅读样式 |

逻辑流程：用户命令进入阅读控制器；控制器调用导入、存储和记录模块；Webview 只通过消息提交阅读动作，不直接操作本地文件。

## 3. 书籍导入与统一正文

### 3.1 导入过程

1. 使用系统文件选择框选择 EPUB/TXT，检查格式与 50 MiB 文件限制。
2. 将文件复制到插件数据目录中的临时位置，并对实际复制的字节流计算 SHA-256，作为书籍 ID；复制过程中继续检查大小上限。
3. 重复文件清理临时副本并返回已有书籍；其他文件从该临时副本解析，确保哈希与解析内容一致。
4. 提取元数据、正文和目录，生成统一正文缓存；无正文或解析失败则终止。
5. 正文及副本写入完成后，再提交书架条目；取消或失败时清理临时内容。
6. 批量导入逐本执行，汇总成功、重复和失败结果，不为此引入后台任务系统。

### 3.2 TXT

- UTF-8 BOM 或严格 UTF-8 检查通过时使用 UTF-8；否则尝试 GB18030，兼容常见 GBK 文本。
- GB 编码回退时先展示短预览，用户可以在支持编码中手选；不声称能准确识别所有未知编码。
- 统一换行为 `\n`，移除 BOM，保留有意义的段落，不对正文进行繁简转换或改写。
- 使用少量固定规则识别常见章节标题；未匹配时仍可阅读。

建议使用 [iconv-lite](https://github.com/pillarjs/iconv-lite) 处理 GB 编码，UTF-8 检查使用运行时原生能力。

### 3.3 EPUB

1. 将 EPUB 作为 ZIP 读取，通过 `META-INF/container.xml` 找到包文件。
2. 读取包文件中的元数据、manifest 和 spine，按 spine 顺序读取正文文档，不能按 ZIP 文件名排序。
3. 优先读取 EPUB 3 Navigation Document，其次读取 EPUB 2 NCX；目录缺失时用正文标题生成扁平目录。
4. 解析正文文档的标题、段落、换行及目录目标锚点，转为规范化文本，保留目录到正文位置的映射。
5. 不加载书内脚本、远程资源、图片或原始样式；不直接把 EPUB HTML 插入 Webview。
6. 检测到正文加密、固定版式或没有可读文字时给出明确失败原因；不把仅有字体混淆的文件一概判为正文加密。

以上顺序依据 [W3C EPUB 3.3 规范](https://www.w3.org/TR/epub-33/)。ZIP、XML、HTML 解析分别建议采用 [yauzl](https://github.com/thejoshwolfe/yauzl)、[fast-xml-parser](https://github.com/NaturalIntelligence/fast-xml-parser)、[parse5](https://github.com/inikulin/parse5)，不自行实现这些格式解析器。

只读取所需 ZIP 条目，不整体解压到项目目录。对路径做归一化和越界检查，并限制条目数、单条目及累计实际解压字节数；XML 禁止外部实体与自定义实体展开。具体解析参数在编码时随锁定的依赖版本确认。

### 3.4 统一正文结构

| 对象 | 主要字段 |
| --- | --- |
| 书籍内容 | 规范化版本、书籍 ID、各段正文、全书文本长度、目录 |
| 正文段 | 稳定段 ID、标题、文本、在全书中的起始偏移 |
| 目录项 | 标题、正文段 ID、段内偏移；界面先显示扁平列表 |
| 阅读位置 | 正文段 ID、段内字符偏移、是否到达全书末尾 |

字符偏移统一采用 JavaScript 字符串的 UTF-16 单元，进度计算与位置恢复采用同一口径；渲染切分时避免拆开代理对。这里的“文本长度”不作为字数或阅读速度分析。

正文按章组织，超长章节按段落再分块。阅读载荷只发送当前逻辑章节的文本；浏览器使用 CSS 多栏、Range 测量分页，通常以约 16K 字符的测量块计算页首偏移，仅将当前块置入可见 DOM。非末块的最后一页带入下一块重排，避免人为分块造成漏字或多余短页；仅保存当前章节最近一次排版结果，尺寸或字体变化时重算。存储分块不作为章节边界。

## 4. 阅读容器与隐蔽操作

### 4.1 一套状态，三个容器

- `sidebar`：在 `explorer` 下声明 `Workspace Notes` Webview 视图。
- `editor`：创建标题为 `notes.log` 的 Webview 编辑器标签，使用文件页样式。
- `panel`：先注册自有阅读视图，选择模式时调用 VS Code 内置 `vscode.moveViews`，将阅读视图移入 `terminal` 容器；把面板定位到底部，原生 Terminal 在左，阅读视图在右。通过 `localReader.panelActive` 控制阅读视图的可见性，隐藏时保留终端与进程。
- `library`：新增 Activity Bar `Local Reader` 书本图标，对应 `localReader.libraryView`，直接展示书架与统计管理页面。
- 0.3 在同一管理视图增加设置页面，保存到原有 VS Code 应用级配置；新增 `localReader.panelReaderSide`，默认 `right`。页面有排版与分栏预览，保存输入同时在前后端校验。
- 布局排序通过聚焦原生 Terminal，再执行 `views.moveViewLeft` / `views.moveViewRight`，最后返回阅读焦点。避免直接在 Webview 的浮层 iframe 上调用依赖视图焦点的移动命令；同时用操作队列及当前页面检查，防止隐藏后延迟操作继续生效。

容器注册方式来自 [VS Code Contribution Points](https://code.visualstudio.com/api/references/contribution-points#contributes.viewsContainers)。原生终端容器由 VS Code 管理；只移动插件自身的阅读视图，不移动终端、不注入命令。视图移动命令属于 VS Code 内置命令，已在 1.144.0 的集成测试中运行验证。

切换时先取得并保存当前位置，清除旧容器正文，再在目标容器恢复位置。控制器只接受当前活动容器的消息，旧容器延迟到达的位置事件不能覆盖新位置。切换期间不额外创建阅读会话。

进入书架或统计页面时暂时清除正文并暂停计时，返回阅读后恢复；管理页面本身不更新正文活跃时间。

持久化状态由扩展宿主管理。Webview 的 `getState/setState` 仅用于短暂界面恢复，不作为书籍进度的唯一来源；不默认启用 `retainContextWhenHidden`，重建时重新获取当前位置。

### 4.2 快捷键与命令

命令前缀为 `localReader`，命令覆盖：导入、打开书架、继续阅读、隐藏、左右翻页、前后章节、模式切换、查看记录与统计。导入按钮仅在书架出现，保留命令面板导入命令。

- `Ctrl+Alt+R` 继续阅读，`Ctrl+Alt+H` 隐藏插件内容。
- Webview 内用 `Left/Right` 翻页、`Alt+Left/Right` 切章、`Esc` 隐藏；阻止滚轮及上下翻页动作。顶部显示书名和章节及两组左右按钮，底部显示本章页码。
- VS Code 命令快捷键使用 `when` 条件；Webview 内排除输入框、选择框、弹层及输入法组合输入。
- 鼠标菜单和快捷键都调用同一组命令，不维护两套翻页逻辑。
- 正文使用事件坐标判断左/右三分之一点击区，复用现有分页入口，不添加遮挡文字的浮层；通过指针移动、选区和修饰键检查排除拖动、选字及其他点击操作，菜单或目录打开时不触发背景翻页。
- 键位冲突交由 VS Code 快捷键设置修改，不额外开发快捷键配置页面。

条件绑定依据 [when clause contexts](https://code.visualstudio.com/api/references/when-clause-contexts)。隐藏快捷键必须实际验证在代码编辑器、插件 Webview 和真实终端分别获得焦点时的行为。

### 4.3 隐藏与重启

隐藏命令按以下顺序执行：

1. 立即将控制器切为隐藏状态，停止计时，拒绝旧视图的正文恢复消息。
2. 清空所有已创建插件 Webview 的正文、书名、目录、书架、记录和统计内容；清除相应界面缓存状态。
3. 关闭插件自己的编辑器标签，停用底部阅读视图并收起活动栏书架，侧栏阅读视图显示中性占位，不关闭真实终端和其他编辑器标签。
4. 将内存中的最新位置和会话保存到磁盘；磁盘写入不阻塞视觉隐藏。

应用重启后，即使 VS Code 恢复了插件视图位置，也先显示占位内容。只有用户主动触发继续阅读或打开管理界面才展示数据。用户已隐藏的内容不能因视图重新可见自动恢复。

## 5. 本地存储与数据模型

### 5.1 存储位置

在 `globalStorageUri` 下保存：

| 路径 | 内容 |
| --- | --- |
| `state.json` | 书架元数据、阅读位置、阅读会话、最近书籍和模式 |
| `state.json.bak` | 上一次完整状态的备份 |
| `books/<bookId>/source.epub` 或 `source.txt` | 导入副本 |
| `books/<bookId>/content.json` | 统一正文和目录缓存 |
| `tmp/` | 尚未提交的导入临时文件 |

不把书籍正文写入 `globalState`、工作区配置或项目目录，也不将阅读数据加入 Settings Sync。全局存储目录的用途见 [ExtensionContext.globalStorageUri](https://code.visualstudio.com/api/references/vscode-api#ExtensionContext)。

### 5.2 必要记录

| 数据 | 字段与含义 |
| --- | --- |
| 书籍记录 | ID、格式、原书名、显示书名、作者、导入时间、编码、最近阅读时间、当前位置 |
| 阅读会话 | 会话 ID、书籍 ID、开始/结束时间、起止位置、按本地日期拆分的有效秒数 |
| 界面偏好 | 最近阅读书籍 ID、最近模式；字号、行高等使用 VS Code 配置项 |

时长统计直接从阅读会话的日期分段聚合，不维护重复的每日汇总表。记录展示按书籍 ID 与本地日期合并，累计有效秒数并取最早/最晚会话进度；没有有效秒数时不显示。历史跨日会话只保存会话首末位置，没有逐日位置快照时省略当天进度范围。原始会话和数据格式保留，无需迁移。

保存基础 `schemaVersion` 和正文规范化版本，防止后续版本误读旧数据；首版不开发通用迁移框架。缓存缺失时用副本重建，规范化不变时位置保持可复用。

### 5.3 写入与恢复

- 同一进程内串行写入；位置变更短暂防抖，时长至少每 15 秒检查点保存。
- 隐藏、切书、关闭阅读器、窗口失焦时立即提交当前检查点；不能只依赖退出时的清理函数。
- 状态文件采用同目录临时文件写入后替换，并保留上一份完整备份；磁盘失败保留可用旧状态并提示。
- 多 VS Code 窗口共享目录时，写入前使用短时文件锁，在锁内重新读取最新状态再应用本次变更，避免整份旧快照覆盖其他窗口的数据。可使用 [proper-lockfile](https://github.com/moxystudio/node-proper-lockfile)，不开发窗口间同步服务。
- 不承诺窗口间实时刷新；主动打开书架或书籍时读取最新状态。同书进度以最近一次明确阅读操作为准，普通时长检查点不回写陈旧位置。
- 移除书籍后拒绝旧会话或旧视图继续写回该书，防止其他窗口把已移除书籍重新加入。

## 6. 位置恢复与计时

### 6.1 位置恢复

每一页保留其对应的规范化文本偏移。左右翻页后将该页起点映射为正文段 ID 与段内偏移并保存；到达最后一页时设置末尾标记。章节切换采用目录绝对边界，不按存储分块切章。

恢复时排版当前章节，定位到包含该字符的页面；仅由缩放触发的重排不覆盖原字符位置。字体族使用 VS Code 的 `--vscode-font-family`，字号默认读取编辑器设置；三种模式共用分页逻辑。百分比从稳定位置计算，动态页码不参与持久化。

### 6.2 计时状态

只需要四种状态：`hidden`、`reading`、`paused`、`idle`。书架和统计界面不进入 `reading`。

| 事件 | 处理 |
| --- | --- |
| 正文首次展示 / 用户继续阅读 | 创建或恢复会话，更新最后正文操作时间 |
| 正文操作 | 更新活跃时间；满足可见及前台条件时开始累计 |
| 阅读区域不可见 / VS Code 失焦 | 截止事件发生时间结算并暂停 |
| 距上次正文操作达到 120 秒 | 只累计到该阈值，进入空闲；恢复时不补记间隔 |
| 切换阅读模式 | 保存位置，沿用会话；只对实际可见时间计时 |
| 隐藏 / 关闭 / 切书 | 结束当前会话并立即保存 |
| 异常退出后再次启动 | 把未结束会话封口到最近检查点，不计离线间隔 |

窗口与视图变化分别使用 `window.onDidChangeWindowState`、WebviewPanel 状态事件和 WebviewView 可见性事件。API 定义见 [VS Code API](https://code.visualstudio.com/api/references/vscode-api)。Webview 只报告自身正文操作，计时以扩展宿主为准，页面定时消息不能视为用户活跃。

有效时长使用单调时钟求差，墙上时间用于时间展示和本地日期归属。每次结算同时截断到失焦、隐藏或空闲阈值；检测到系统休眠造成的明显长间隔时暂停，不把该间隔补入。跨午夜只拆有效区间。

每个会话以自身累计秒数覆盖检查点，不能反复累加同一检查点。图表与所有汇总共用同一聚合函数，避免统计口径分叉。

## 7. 页面安全与性能边界

- 正文以文本节点显示；书名、目录标题及文件名同样按文本处理。
- Webview 设置严格 CSP，只允许插件自身所需脚本和样式，禁止书内脚本及网络访问；消息只接受约定动作并校验书籍 ID、位置和当前容器。
- 导入内容不能触发任意 VS Code 命令或文件读写；错误日志不默认输出正文和阅读记录。
- 全书只在导入时规范化，阅读时复用缓存；只保持一本活动书，不为三种外观各存一份正文状态。
- 导入按文件和正文块分步处理，及时让出扩展宿主执行时间；只有实测出现明显阻塞才增加 Worker，不预先搭建任务调度系统。
- 最近 7 天图使用简单 HTML/CSS 柱状图和数字说明，不引入图表库。

Webview 限制依据 [官方安全与状态管理说明](https://code.visualstudio.com/api/extension-guides/webview#security)。性能以 PRD 中的目标和后续实测为准，不把尚未测试的性能写成交付事实。

## 8. 编码实施顺序

四步均属于同一首版，不因分步而缩减三种模式或统计需求。

| 步骤 | 工作内容 | 阶段验证 |
| --- | --- | --- |
| 1. 导入与书架 | 扩展骨架、TXT/EPUB 解析、统一正文、本地存储、书架列表 | 常见格式、重复、乱码预览、失败隔离、删除原文件后仍可读 |
| 2. 阅读与恢复 | 先贯通一个容器，再复用到侧栏/编辑器/底部；加入目录、翻页、位置保存 | 三模式位置一致，调字号和重启后可继续 |

## 9. 验证方案

**自动验证聚焦数据正确性**：
